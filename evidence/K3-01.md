- Различия CI / Continuous Delivery / Continuous Deployment:

Continuous Integration (CI): Автоматическая проверка каждого изменения (тесты, линтеры) при слиянии кода разработчиков и фокус на раннем обнаружении дефектов.
Continuous Delivery (CD): Автоматическая подготовка проверенного артефакта (например, Docker-образа) к релизу. Перевод готового продукта на рабочий сервер выполняется по решению человека.
Continuous Deployment (CD): Полностью автоматический процесс: каждое изменение, успешно прошедшее проверки, автоматически и без участия человека развертывается в рабочей среде.

- Сравнение с Git-flow и обоснование выбора:
Git-flow предполагает сложную структуру веток (master, develop, feature, release и т.д.).
Выбранная схема (GitHub Flow / Short-lived Feature Branches) использует только основную ветку main и короткоживущие ветки задач. Для небольшого проекта из 1–2 сервисов и одного разработчика эта схема самая удобная: она исключает расходы на слияния веток, снижает вероятность конфликтов и обеспечивает максимальную скорость обратной связи от конвейера.

- Этап получения обратной связи:
Обратная связь появляется на этапе выполнения проверок в Pull Request. Разработчик видит статус сборки прямо на странице PR: в случае падения теста GitHub помечает PR красным крестом, блокирует кнопку слияния и предоставляет ссылку на детальный лог упавшего шага.

- Ответ на вопрос из задания:
Является ли сборка образа автоматическим deployment?

Нет, не является. Сборка Docker-образа - это этап непрерывной доставки, в результате которого создается готовый образ приложения. Deployment (развёртывание) - это отдельный процесс доставки и запуска этого артефакта в среде исполнения (например на сервере) с настройкой сети, томов и конфигурации.
