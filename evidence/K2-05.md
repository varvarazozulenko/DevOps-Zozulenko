# Работа K2-05

- Группа: 9.24.2
- Код студента (без ФИО): 08072004
- Что сделано: 
  В файле `compose.student.yaml` допущена ошибка конфигурации, т.е. порт в `API_URL` сервиса `web` изменен с 8000 на 9999. Конфигурация применена через Compose. Пояивлась ошибка в пользовательском интерфейсе и в логах. После фиксации порт изменила на 8000, настройки изменены заново, подтверждена отправка новой заявки.

- Команды и существенный вывод:
  1. Изменение настройки на `API_URL: http://api:9999`.
  2. `docker compose -f compose.student.yaml up -d web` - пересоздание контейнера веб-части с новыми параметрами окружения.
  3. `docker compose -f compose.student.yaml logs web --tail 20` - фиксация ошибки подключения:
     `{"role": "web", "event": "upstream_unavailable", "target": "http://api:9999", "error": "<urlopen error [Errno 111] Connection refused>"}`
     `{"role": "web", "event": "http", "method": "GET", "path": "/api/requests", "detail": "\"GET /api/requests HTTP/1.1\" 503 -"}`
  4. Возврат порта: `API_URL: http://api:8000`.
  5. `docker compose -f compose.student.yaml up -d web` - повторное применение исправленной конфигурации.

- Ожидал: 
  При обращении к несуществующему порту 9999 веб-интерфейс не сможет получить и отправить заявки.

- Получил: 
  В браузере на `localhost:8080` перестали загружаться заявки, при попытке создания возвращалась ошибка 503. В логах зафиксирован отказ в соединении с `api:9999`. После возврата порта 8000 список заявок снова отобразился, новая заявка успешно отправлена и сохранена.

- Почему это подтверждает результат: 
  Служба `api` слушает входящие соединения только на порту 8000. Попытка обратиться на порт 9999 внутри сети приводит к ошибке сетевого сокета `[Errno 111] Connection refused`, так как порт 9999 закрыт. При этом сам контейнер web продолжал работать.

- Ошибка и её исправление (если были): 
  Намеренная ошибка сетевого порта исправлена возвратом значения `http://api:8000` в файле `compose.student.yaml`.

- Ответ на вопрос из задания: 
   Какой порт должен использовать web для обращения к api внутри сети Compose: 8080 или 8000? Почему?
   Сервис `web` должен использовать порт 8000. Внутри изолированной bridge-сети Docker Compose контейнеры общаются напрямую по внутренним портам приложений. Порт 8080 выполнен исключительно на хост-компьютер для доступа через внешний браузер и во внутренней сети контейнеров не используется.
