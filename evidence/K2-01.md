# Работа K2-01

- Группа: 9.24.2

- Что сделано: 
  Запущен стенд, исследованы параметры базового образа devops-course:base и роли запущенных контейнеров web и api. Проверено поведение системы при остановке сервиса web и отправка заявки после его повторного старта.

- Команды и существенный вывод:
  1. `docker compose ps` - показал два запущенных контейнера: devops-course-web-1 (порт 127.0.0.1:8080->8000) и devops-course-api-1 (порт 8000). Оба используют один образ devops-course:base.
  2. `docker image inspect devops-course:base` — показал метаданные базового образа: среда Python, WorkingDir /app, volume /data, порт 8000.
  3. `docker compose stop web` - остановил контейнер devops-course-web-1 (перешел в Exited).
  4. `docker compose start web` - вернул контейнер web в статус Up.

- Ожидал: 
  При остановке web страница в браузере перестанет открываться, но api останется запущенным. При запуске web страница снова откроется, а отправленная заявка дойдет до api и сохранится.

- Получил: 
  При остановленном web браузер выдал ошибку подключения на http://localhost:8080. После `docker compose start web` страница открылась, тестовая заявка успешно создана и отобразилась в интерфейсе.

- Почему это подтверждает результат: 
  Это подтверждает, что web и api работают как независимые контейнеры с разными ролями из одного образа. Остановка веб-интерфейса не уничтожает бэкенд, а после старта связь между сервисами восстанавливается.

- Ошибка и её исправление (если были): 
  В начале работы Docker не был доступен из дистрибутива WSL. Ошибка исправлена включением WSL Integration в настройках Docker Desktop и перезагрузкой WSL через команду `wsl --shutdown`.

- Ответ на вопрос из задания: 
  Удаляется ли образ, когда вы останавливаете web?
  Ответ: Нет, не удаляется. Образ - это неизменяемый шаблон файловой системы и настроек, хранящийся в кэше Docker. Остановка останавливает лишь запущенный процесс контейнера, сам образ остается на диске.
